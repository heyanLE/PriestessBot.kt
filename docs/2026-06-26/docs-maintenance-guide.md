# 文档维护指南

日期：2026-06-26

这份文档说明当代码继续演进时，文档应该怎么同步，避免导读体系慢慢失效。

## 什么时候改模块页

当变化只落在某个模块内部时，优先更新对应模块页。

例如：
- 新增 `Case` 方法
- 新增子目录或核心类
- 模块内部职责变化
- 模块流程图需要更新

## 什么时候改横切页

当变化影响主链路时，必须更新横切页。

例如：
- 平台消息进入和回复路径变化
- Agent / LLM / Tool 链路变化
- workspace / skill / persona 注入变化
- 配置或重载行为变化

对应文档：
- `message-flow.md`
- `llm-flow.md`
- `feature-delivery-workflow.md`

## 什么时候改导航页

当需求影响“从哪里开始看”时，优先更新导航类文档。

对应文档：
- `navigation-map.md`
- `repository-tour.md`
- `role-reading-paths.md`
- `newcomer-faq.md`

## 什么时候改协作文档

当角色分工、交接方式、推进顺序变化时，更新协作文档。

对应文档：
- `multi-role-collaboration.md`
- `feature-delivery-workflow.md`

## 什么时候改本地开发页

当启动方式、验证方式、构建方式变化时，更新本地开发页。

对应文档：
- `local-dev-and-verification.md`

## 什么时候改索引

只要新增、删除、重命名文档，都应该同步 `index.md`。

索引的职责：
- 把所有文档聚在一起
- 给新人一个唯一入口
- 让不同角色能迅速跳到自己的阅读路径

## 推荐维护顺序

1. 先改模块页或横切页。
2. 再改导航或 FAQ。
3. 再改协作和角色阅读路径。
4. 最后更新 `index.md`。

## 维护原则

- 一个新概念，至少要有一个能定位到代码的位置。
- 一个新功能，至少要有一条横切流程说明。
- 一个新入口，至少要能从索引直接找到。
- 一次跨模块改动，最好同时更新协作和交付流程页。
