# v3 里程碑三期

v3 目标是从「功能可用」推进到「质量可靠、Agent 能力完整、运行时可热更新、人格记忆可管理」。本期不追求继续堆新平台，而是围绕功能优化补齐工程可信度和聊天 Agent 的核心体验。

## 背景现状

截至 2026-06-24，系统已经具备 v1/v2 的主体能力：

- IM 平台抽象与 Telegram/NapCat 适配。
- 9 阶段消息 Pipeline。
- ReAct Agent 循环和上下文压缩策略。
- OpenAI/Ollama/Anthropic/Gemini Provider。
- Tool/MCP 基础设施和一批内建工具。
- Dashboard API/前端、配置热更新、插件生命周期、插件注册 Tool/Provider/Platform。
- 知识库关键词检索、子 Agent 路由、Prometheus 指标、健康检查、配置备份恢复。

v3 的核心问题是：这些能力已经散落可用，但还需要系统化测试、默认工具补齐、配置工作区化、人格与记忆一体化，才能让系统进入可长期迭代的状态。

## v3 总目标

1. 测试覆盖提升：建立单元测试、集成测试、系统测试、回归测试的分层测试体系。
2. 核心 Tool 补齐：对齐 AstrBot 常用核心工具，让无插件场景也具备聊天 Agent 的基础行动能力。
3. 工作区与热重载：新增 workspace 概念，统一管理 skill、MCP、tool、agent/persona、memory 等配置，并支持热重载。
4. 人格和记忆管理：新增 persona 与 memory 管理模块，支持 Dashboard 管理、Agent 注入、记忆检索与持久化。
5. 文档和模块边界清晰：每个模块都有接口、状态、验收标准、测试要求和执行任务。

## 新增代码规范

v3 起新增模块边界规范，详见 `docs/2026-06-24/code-architecture-guidelines.md`：

1. 所有继承 `BaseController` 的生产类必须以 `Controller` 结尾。
2. 模块间依赖尽量只注入 `Case`，不要跨包直接注入 Controller 或模块内部类；Case 负责暴露稳定的 `getXX`、`list`、`resolve`、`reload`、`stop` 等能力。

当前已新增架构测试扫描 `BaseController` 子类命名，后续跨包 Controller 依赖会按模块逐步收敛到 Case 门面。

## v3 模块划分

### testing-quality

建立测试基础设施和覆盖门槛，优先覆盖高风险核心链路：

- ReActRunner 循环、工具调用、异常与 maxSteps。
- Pipeline 9 阶段 stop/flow/onion 行为。
- Provider adapter 请求/响应解析。
- ToolExecutor 参数解析、未知工具、异常封装、指标。
- Config reload、workspace reload、plugin contribution cleanup。
- Dashboard API contract。
- 平台 adapter 事件解析和发送行为。

### core-tools

补齐无插件默认 tool：

- 消息动作：发送、早回复、引用/分段回复能力。
- 信息检索：web search、URL fetch、knowledge search。
- 会话与记忆：conversation search、memory save/recall。
- 时间任务：reminder/todo 基础工具。
- 诊断：system info、health、list tools。
- 安全受控的 workspace 文件读取/搜索。

高风险工具如 shell、任意文件写入、浏览器自动化、群管理动作不作为默认开启能力，必须通过权限配置启用。

### workspace-runtime

新增 workspace 作为运行时配置作用域：

- 每个 workspace 拥有独立 skill、MCP、tool、agent、persona、memory 配置。
- 支持文件 watcher 或显式 API reload。
- reload 需要有变更摘要、校验、失败回滚。
- Pipeline/Agent 执行时可解析当前会话对应 workspace。
- Dashboard 可查看 workspace 状态和 reload 结果。

### persona-memory

人格和记忆管理成为 Agent 上下文的一等能力：

- Persona：人格名、说明、语气、边界、系统提示词模板、适用 workspace/agent。
- Memory：事实记忆、偏好记忆、事件记忆、摘要记忆。
- 支持记忆写入、检索、删除、过期、作用域隔离。
- Agent prompt 注入需要可解释，可在 Dashboard 查看本轮注入了哪些 persona/memory。

## 里程碑拆分

### v3.1 测试底座

- 梳理测试矩阵。
- 补齐核心单元测试。
- 建立系统测试 fixture。
- 增加 CI 可执行测试命令说明。

### v3.2 核心工具

- 定义核心 tool schema 和权限模型。
- 实现 reminder、conversation search、memory tool、URL fetch、list tools。
- 为现有内建 tool 增加权限和测试。

### v3.3 Workspace 热重载

- 建立 WorkspaceConfig 和 WorkspaceController。
- 支持 skill/MCP/tool/persona/memory 配置 reload。
- Dashboard 增加 workspace API 和页面。

### v3.4 Persona/Memory

- 实现 PersonaController、MemoryController、MemoryRetriever。
- AgentContext 集成人格与记忆注入。
- Dashboard 支持管理和检索测试。

### v3.5 系统验收

- 用系统测试覆盖 NapCat/Telegram mock -> Pipeline -> Agent -> Tool -> Respond。
- 验证 workspace reload 不影响正在执行的消息。
- 验证人格/记忆注入与删除/过期行为。
- 更新 docs 与 roadmap 状态。

## 验收标准

- `./gradlew test` 通过。
- 新增系统测试可在本地无真实外部平台凭据时运行。
- 所有核心 tool 有 schema、权限、成功/失败测试。
- workspace reload 有原子性：失败不污染当前运行配置。
- persona/memory 能通过 API 创建、查询、注入、删除。
- Dashboard 能显示 workspace、persona、memory、核心 tool 状态。
- 文档中每个 v3 模块都有接口、任务、验收和风险说明。
